# 手势花活：隔空召唤你的减肥数据

两只手并拢、唰地往两边一拉，数据从两手中间炸开，聚成你自己的体重曲线；两只手再一合，数据被压碎炸散。捏住一根线沿线滑，读出那一天的体重和备注。发朋友圈用的。

画面只在你电脑上处理，不上传、不存帧。

## 怎么开

跟你的 Agent 说「打开减肥教练的手势页」，或者在这个文件夹里打开命令行，跑：

```
python3 show.py
```

Windows 上把 `python3` 换成 `python`。不用装别的。

1. **用 Chrome。** 上面的命令会尽量用 Chrome 打开；开到别的浏览器的话，把命令行打印的地址贴到 Chrome。
2. **点允许摄像头。** 地址栏会弹一次；macOS 第一次还会弹系统权限，也要点允许。
3. **等左上角变成 `TRACKING`。** 第一次要联网下载手势模型（约 8 MB，来自 Google），之后有缓存。下载不了就开代理再刷新。

关掉命令行窗口就结束了。

## 手势

先站到手和上半身都在画面里的位置，手抬到胸口高度就够，不用举高。左右手都行，手心朝镜头最稳。

| 想做什么 | 怎么比 | 会发生什么 |
|---|---|---|
| **唰开（召唤）** | 两只手都张开、并拢，**一起快速往两边拉** | 不用等，拉到一半就从两手中间炸开，比单手版更猛 |
| **合拢（消散）** | 两只手都张开、分在两边，**一起快速合到一起** | 数据被压进两手中间炸散 |
| **单手召唤（备用）** | 张开手掌，整只手进画面，**停住不动** | 手上的圈转满（0.8 秒）就触发 |
| **转动** | 拇指食指一捏（比 OK 也算），捏在**空白处**，拖动 | 视图跟手转 |
| **读数** | 捏在**一根线上**，沿线滑 | 线亮起来，读数跟着手指走：日期、体重、7 天平均、备注 |
| **缩放** | **两只手都捏住**，拉开或合拢，先捏哪只都行 | 拉开放大、合拢缩小，一起挪动就移位置 |
| **定住** | 手指一分开 | 视图当场定住，手怎么动都不跟 |
| **单手消散（备用）** | 握拳，整只手在画面内，**停住不动** | 手上的圈转满就炸散 |

只有捏住时视图才动，捏着拉开合拢永远是缩放，不会触发唰开和合拢。手指快合上时，指尖的绿圈会跟着收，会抓到的那根线也先亮一下；捏上的一刻圈收成实心点。

张手和握拳没反应？看手上方的提示：「整只手进画面」是手离画面边缘太近，「停住不动」是手还在动。这是故意的，不然手一举起来就会误触发。

唰开和合拢没反应？两只手都要张开、都在画面里，两只手都要动，只动一只不算；动作要快，慢慢拉开也不算；要往两边拉，不算上下。刚松开捏合的 0.5 秒内不算，刚合拢消散的 0.9 秒内也不会弹回来。两手并在一起时会提示「向两侧唰地拉开」，这时不走单手停住那条路。

## 数据从哪来

- 用过 weight-loss-coach：自动读 `~/weight-loss-data` 里的 `plan.md` 和 `log.md`，左上角显示 `YOUR DATA 你的数据`，每次刷新都是最新的。
- 还没用过，或者一条体重记录都没有：显示编好的示例数据，左上角写 `SAMPLE DATA 示例数据`。记了第一条就显示你的：一个点、计划线和数字。
- 数据放在别处：`python3 show.py --data 路径`。录屏不想露真实体重：`python3 show.py --sample`。

## 不顺手就调（加在网址后面）

每个人的摄像头、手、光线都不一样，调这几个就够了，例如 `http://127.0.0.1:8765/?pin=.35&rot=.7`：

| 现象 | 参数 | 默认 | 怎么调 |
|---|---|---|---|
| 老是捏不住 / 没捏也算捏住 | `pin` | .28 | 调大 / 调小 |
| 转得太快 / 太慢 | `rot` | 1 | 调小 / 调大 |
| 老抓到线、转不了 / 老抓不到线 | `hit` | .5 | 调小（0 = 不抓线）/ 调大 |
| 视图发抖 | `fc` | 1.5 | 调小，先试 1 |
| 手快的时候视图跟不上 | `beta` | 2 | 调大，先试 4 |
| 唰开和合拢老是没反应 / 老误触发 | `swipe` | 8 | 两手间距每秒变化几个手掌长，调小 / 调大 |
| 两手多近才算并拢 | `near` | 2.5 | 手掌中心相距几个手掌长，调大更松 |
| 两手至少要动多远 | `sweep` | 1.5 | 手掌长，调大要动得更远才触发 |
| 单手召唤和消散太慢 / 老误触发 | `hold` | .8 | 秒数，调小 / 调大 |
| 手离边多远才算在画面内 | `edge` | .5 | 画面高是 10，调大更严 |
| 手要多稳才算停住 | `still` | 1.2 | 每秒移动几个手掌长，调小更严 |
| 视图追手的速度 | `follow` | 35 | 调大更紧，调小更柔 |
| 人像亮度 / 粒子数 | `dim` / `n` | .92 / .8 | 电脑卡就把 `n` 调到 .5 |

## 手机版

`mobile.html` 是一个自带手势模型的单文件（约 10 MB），放到任何 https 网页托管上，手机打开就能玩，不用电脑。里面只有编好的示例数据，画面只在手机上处理，不上传不存帧。

它由 `build_mobile.py` 从 `index.html` 生成，手势、动效和判据是同一份，别手改 `mobile.html`。改了 `index.html` 就重跑：

```
python3 build_mobile.py
```

和电脑版不一样的地方：

- 画面铺满手机屏幕，竖屏时两翼挪到曲线下面。
- `C` `F` `H` 键换成屏幕右上角的按钮：前后（切前后摄像头）、全屏、文字。iPhone Safari 没有网页全屏，这个按钮不显示。
- 底部只列现在能做的手势。
- 掉帧就自动降粒子数和分辨率，最低一档关掉泛光。
- 竖屏只装得下四五个手掌宽，双手唰开和合拢的最小行程从 1.5 放宽到 1.1 个手掌长。双手玩横屏更顺手。

手大约要离手机 80 厘米以内（估的：用照片测出手掌要占画面长边 9% 以上），再远模型就认不出来了。

拿不到摄像头时页面会提示；托管页面的 iframe 不给摄像头权限，就要换一个能直接打开的 https 地址。另存到电脑上用 Chrome 打开也能用；手机上直接打开本地文件多半拿不到摄像头。

## 检查

- `python3 show.py --selftest` 查读数据那部分，也查 `mobile.html` 有没有过期。
- 网址加 `?test`，结果写在网页标题，`SELFTEST OK` 算过：7 天平均对照示例的复盘数字、手型识别、手势规则、滤波。
- `?video=xxx.mp4` 用视频代替摄像头跑整条链路，视频放这个文件夹。这个模式按视频时间算手势，慢放也准。
